# Real-Time Crypto Data Pipeline

End-to-end data pipeline для сбора и обработки данных о криптовалютном рынке в реальном времени.

Проект получает данные с Binance, передаёт события через Apache Kafka, сохраняет их в PostgreSQL, преобразует с помощью dbt и оркестрирует процессы с помощью Apache Airflow.

Проект предназначен для практики построения полного data pipeline: от получения данных из внешнего API до формирования аналитических моделей в DWH.

## Что делает pipeline

Pipeline непрерывно получает данные о криптовалютном рынке и проходит несколько этапов обработки:

1. Python Producer асинхронно получает данные с Binance.
2. Полученные события публикуются в Kafka.
3. Python Consumer читает сообщения из Kafka.
4. Сообщения накапливаются в батчи и записываются в PostgreSQL.
5. Kafka offsets фиксируются только после успешной записи данных.
6. dbt преобразует данные в аналитические модели.
7. Airflow управляет последовательностью выполнения задач.

Таким образом, внешнее API, streaming layer, хранилище и слой трансформации разделены между собой.

## Основные инженерные решения

### Асинхронный сбор данных

Producer использует `asyncio`, `aiohttp` и `aiokafka` для асинхронного получения данных и их публикации в Kafka.

Это позволяет не блокировать выполнение во время ожидания сетевых запросов.

### Kafka как промежуточный streaming layer

Kafka используется для разделения процессов получения и сохранения данных.

Producer и Consumer работают независимо друг от друга, а Kafka выступает промежуточным буфером между внешним API и PostgreSQL.

```text id="flow001"
Binance
   │
   ▼
Producer
   │
   ▼
Kafka
   │
   ▼
Consumer
   │
   ▼
PostgreSQL
```

Такое разделение позволяет независимо масштабировать и изменять компоненты pipeline.

### Батчевая запись в PostgreSQL

Consumer не записывает каждое событие в базу отдельным запросом.

Сообщения накапливаются в памяти и записываются при выполнении одного из условий:

* достигнут заданный размер батча;
* истёк интервал ожидания.

Это уменьшает количество операций записи в PostgreSQL и позволяет эффективнее обрабатывать поток сообщений.

### Manual offset commit

Автоматический commit Kafka offsets отключён.

Offset фиксируется только после успешной записи соответствующего батча в PostgreSQL.

```text id="offset001"
Kafka
  │
  ▼
получение batch
  │
  ▼
запись в PostgreSQL
  │
  ├── ошибка ──► retry
  │
  └── успех ──► commit offset
```

Таким образом, Consumer не подтверждает обработку сообщения до того, как данные были успешно сохранены.

При ошибке записи предусмотрен механизм повторных попыток.

### Трансформации с dbt

Трансформационный слой реализован с помощью dbt.

Модели разделены на несколько уровней:

```text id="dbt001"
Raw data
   │
   ▼
Staging
   │
   ▼
Marts
   │
   ▼
Аналитические модели
```

Такой подход позволяет отделить ingestion от бизнес-трансформаций и поддерживать структуру аналитического слоя независимо от процесса загрузки данных.

### Оркестрация с Airflow

Apache Airflow используется для управления процессами обработки данных.

DAG определяет последовательность выполнения задач и позволяет запускать трансформационный pipeline по расписанию.

Для Airflow используется отдельная PostgreSQL database для хранения metadata, изолированная от аналитического DWH.

### Контейнеризация

Все основные компоненты запускаются в Docker.

Окружение описано через Docker Compose и включает сервисы для:

* PostgreSQL DWH;
* Kafka;
* Python Producer;
* Python Consumer;
* Airflow;
* PostgreSQL metadata database для Airflow.

Это позволяет развернуть весь pipeline локально без ручной установки отдельных компонентов.

## Запуск

### Требования

* Docker
* Docker Compose

Создайте файл с необходимыми переменными окружения и запустите проект:

```bash id="run001"
docker compose up -d
```

После запуска Docker Compose поднимает необходимые сервисы и связывает их в общую Docker network.

## Цели проекта

Проект создан для практики построения полноценного data pipeline, а не отдельных ETL-скриптов.

Основные задачи проекта:

* реализация streaming ingestion;
* работа с Apache Kafka;
* асинхронное программирование на Python;
* batch processing;
* управление Kafka offsets;
* сохранение данных в PostgreSQL;
* построение аналитических моделей с dbt;
* оркестрация pipeline с Airflow;
* контейнеризация инфраструктуры с Docker.

## Статус

Проект находится в разработке.

В текущей версии реализованы основные компоненты ingestion и transformation pipeline. Проект продолжает развиваться в направлении оркестрации, контроля качества данных и расширения аналитического слоя.
